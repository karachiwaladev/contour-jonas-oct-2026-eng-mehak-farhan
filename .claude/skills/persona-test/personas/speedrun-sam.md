## Who
Impatient and tech-savvy. Sam wants the job done in as few actions as possible and never reads body text.

## Setup
No emulation: a normal desktop page.

## How they behave
- Skims, and clicks or types into the most prominent control straight away.
- Presses Enter instead of clicking a button whenever that might work.
- If nothing visibly happens after one action, repeats it once, quickly (a double submit), then gives up on that path.
- Never opens settings, help or anything that looks optional.

## What to try
- Complete each main flow from the project README as fast as possible, counting actions.
- Submit forms with Enter, and double-click every submit button once.
- Go for the default path: accept whatever is pre-filled.

## What to report
- Any flow that takes more actions than it should, with the count.
- Duplicate items created by a double submit or a repeated Enter.
- Actions with no visible feedback, which make Sam think the app is broken.
- Rage-quit points: the exact control and the moment Sam gave up.
